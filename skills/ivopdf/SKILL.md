# IvoPDF — HTML/CSS → PDF in pure PHP

IvoPDF renders HTML + CSS to PDF using only PHP (`ext-dom`, `ext-mbstring`, `ext-zlib`; `ext-gd`, `ext-openssl`, `ext-intl` optional). It runs on shared hosting, supports Flexbox, CSS Grid and multi-column (which dompdf lacks), and exposes dompdf- and mPDF-compatible APIs (mPDF tags like `<pagebreak>`, `<htmlpageheader>`, `<columns>` work unchanged). Laravel (`ivopdf/laravel`) and Symfony (`ivopdf/symfony-bundle`) packages exist. License: AGPL-3.0-or-later — mention this if the user is building a closed-source product.

## Workflow

1. **Install / load.** `composer require ivopdf/ivopdf` (then `vendor/autoload.php`), or without Composer `require 'path/to/ivopdf/autoload.php';`.
2. **Write the template as normal HTML + a `<style>` block.** Design it like a print page, not a web page (see "Template rules").
3. **Render** with the minimal code below; add header/footer, metadata, fonts as needed.
4. **Verify** the result — always, because layout bugs are invisible in code: render, check `getPageCount()` and `getWarnings()`, and look at the pages (see "Verify the output"). Fix and re-render until it looks right.

```php
use IvoPdf\IvoPdf;

$pdf = new IvoPdf([
    'paperSize'   => 'A4',              // A0–A6, B4, B5, Letter, Legal, … or [widthPt, heightPt]
    'orientation' => 'portrait',
    'basePath'    => __DIR__ . '/templates',   // where relative <img src>/<link href> are resolved
]);
$pdf->setFooterHtml('<div style="text-align:right;font-size:8pt;color:#64748b">Page {PAGE_NUM} of {PAGE_COUNT}</div>');
$pdf->loadHtml($html);

$pdf->save(__DIR__ . '/out/invoice.pdf');          // or: $bytes = $pdf->output();
// in a web request instead: $pdf->stream('invoice.pdf', ['Attachment' => false]);
print_r($pdf->getWarnings());                      // images not found / blocked, rejected fonts …
```

`loadHtmlFile($path)` sets `basePath` to the file's folder automatically.

## Template rules (why they matter)

- **Units:** use `pt` (1/72 in) or `mm` for print precision. `px` works (96 dpi → 0.75 pt) but mixing units makes alignment drift.
- **Page setup belongs in CSS:** `@page { size: A4 portrait; margin: 20mm 18mm 22mm 18mm; }`. These override constructor margins. The running footer/header reserve space automatically.
- **Box sizing:** the default is CSS-correct `content-box`; add `* { box-sizing: border-box; }` when you size boxes with padding (almost always what you want in documents).
- **Fonts:** bundled families are `Inter` (default sans-serif) and `DejaVu Sans`, `DejaVu Serif`, `DejaVu Sans Mono` (full Cyrillic/Greek/Latin; DejaVu also covers Arabic/Hebrew and fills glyphs Inter lacks). Generic `sans-serif`, Roboto… map to Inter; Arial/Helvetica, Times New Roman and Courier New map to the metric-compatible Liberation Sans/Serif/Mono (same line breaks as in Word/browsers); generic `serif`/`monospace` to DejaVu Serif/Sans Mono. `Sofia Sans` and `Sofia Sans Semi Condensed` are bundled for Bulgarian letterforms (set `<html lang="bg">`; `lang` also selects Serbian/Macedonian/Russian forms where a font has them). For brand fonts use `.ttf` files via `registerFontFamily()` or CSS `@font-face` — see `references/api.md`. Only used glyphs are embedded, so files stay small (~40 KB for an invoice).
- **Layout:** prefer Flexbox/Grid over floats and tables for structure; use real `<table>` for tabular data (it paginates row by row and repeats `<thead>` on every page).
- **Page breaks:** `page-break-before/after: always` (or `break-before: page`, or `<pagebreak />`), `page-break-inside: avoid` on cards/blocks that must stay whole. Headings automatically stay with the following content.
- **Images:** local files are only read from `basePath` / `allowedPaths` (security sandbox); remote URLs need `'isRemoteEnabled' => true`. Data URIs always work. If an image is missing, check `getWarnings()` before anything else.
- **Page numbers:** `{PAGE_NUM}` / `{PAGE_COUNT}` in header/footer HTML, or CSS `content: counter(page) " / " counter(pages)` (dompdf style), or mPDF's `{PAGENO}` / `{nbpg}`.
- **Links & navigation:** `<a href="#id">` becomes a clickable internal link; `h1–h6` become PDF bookmarks automatically.
- **Barcodes:** `<barcode type="QR" value="…" />`, also `DATAMATRIX`, `PDF417`, `C128`, `EAN13`, `UPCA`, `C39`… (vector, Cyrillic-safe QR).
- **Beyond layout:** fillable forms come from plain HTML controls; passwords, digital signatures, PDF/A, PDF/X/CMYK, attachments (Factur-X), letterhead backgrounds from existing PDFs and tables of contents are one method call each — see section 7 of `references/api.md`.
- **Other scripts:** Arabic/Hebrew (RTL, `dir="rtl"`) work with the bundled fonts; Chinese/Japanese/Korean/Indic/Thai need a registered font (`scriptFonts`).
- **Security:** never pass untrusted user HTML with `isRemoteEnabled` on; keep `allowedPaths` minimal.

What is supported in detail (selectors, properties, SVG, tables, limitations) is in `references/css-support.md`. Read it when you need a feature you're unsure about, or when output differs from a browser.

## Verify the output

Do not hand over a PDF you haven't looked at. Use the bundled scripts (paths relative to this skill folder):

```bash
php scripts/render.php template.html out.pdf --paper=A4 --footer="Page {PAGE_NUM} of {PAGE_COUNT}"
```

```bash
python scripts/preview.py out.pdf
```

`render.php` prints page count, size, render time and warnings. `preview.py` rasterizes every page to PNG next to the PDF (needs PyMuPDF: `pip install pymupdf`) and prints the extracted text and bookmarks — open the PNGs to check the layout. If neither Python nor PyMuPDF is available, open the PDF in a browser.

Typical things to check: text not overflowing boxes, columns aligned, nothing cut at page bottoms, totals/numbers right-aligned, images present, Cyrillic rendered (not boxes), the expected number of pages.

## Migrating from dompdf / mPDF

The constructor accepts dompdf and mPDF option names (`format` like `'A4-L'`, `margin_left` in mm, `default_font`, `chroot`, `isRemoteEnabled`), and the familiar methods exist: `loadHtml`, `setPaper`, `render`, `output`, `stream` (dompdf) and `WriteHTML`, `SetHTMLHeader`, `SetHTMLFooter`, `SetWatermarkText`, `AddPage`, `SetTitle`, `output($name, 'I'|'D'|'F'|'S')` (mPDF). Usually only the `use`/`new` line changes. The full mapping table and caveats are in `references/api.md`. After migrating, render a few real documents and compare page by page with the old output.

## Troubleshooting quick table

| Symptom | Likely cause → fix |
|---|---|
| Image missing | Path outside `basePath`/`allowedPaths`, or remote without `isRemoteEnabled` → read `getWarnings()` |
| Boxes wider than expected | `content-box` sizing with padding → `* { box-sizing: border-box }` |
| Empty squares instead of letters | Font lacks the glyph → use DejaVu or register a TTF that has it / `addFallbackFont()` |
| Footer overlaps content | Nothing to do — space is reserved automatically; if very tall, reduce footer height |
| Table row split / lonely heading at page end | Rows never split; add `page-break-inside: avoid` to custom blocks |
| Layout differs from Chrome | Check `references/css-support.md` limitations; simplify the CSS (avoid percentage heights) |
